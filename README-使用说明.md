# 聊天记录自动备份 (Chat Auto Backup) v1.3.2

SillyTavern 扩展。按楼层数自动导出角色卡聊天记录，**每张卡、每个聊天独立计数、独立文件夹**。
实测环境 SillyTavern 1.18.0，兼容 1.14.0+。

---

## ✨ 它能干什么

- 聊天推进到设定楼层就自动导出一份快照，全程静默
- 导出间隔设为 **1～9** 时启用滚动保留：普通备份按聊天默认保留最近 **10 份**（全量模式下第 **10、20、30……** 楼永久保留；「仅 AI 楼层」模式下**每 10 轮 AI 回复**永久保留）
- **「仅 AI 楼层」按真实轮次计数**：只统计非开场白 AI 回复数（如间隔 `2` 表示每 2 次 AI 回复存一档），跳过用户楼与系统提示楼（已隐藏的历史 AI 对话楼仍计入轮次），文件名仍保持界面楼号 `#N` 方便对照
- **空回拦截防误备**：最新楼为空白或空标签时自动延后，等重新生成出有效内容后再存，绝不把空楼层当成完整备份
- **重生成 / 多 Swipe 自动更新**：在授权目录模式下停留在刚备份的楼层重生成、切 Swipe 或编辑时，停手防抖原地覆写更新；迅速进入下一楼时也会自动切片定稿上一里程碑
- **本地直出极速写盘**：JSONL 格式默认直接读取内存 `Blob` 分块写盘，免去网络往返与整档重拷贝；回溯多段历史同样增量 `O(N)` 序列化
- 文件名固定 `角色卡名称——USER名称——楼层数`
- **不同角色卡、同一张卡的不同聊天，计数完全隔离**，永不串账
- 目录自动分层：`角色卡 → 聊天记录 → 备份文件`
- 老卡中途启用也不怕：一键**回溯补齐**过往所有历史段落
- 导出的是标准 JSONL，**可原样回导入酒馆**（含元数据表头，楼号不偏移）

## 📦 安装

1. 把 `chat-autobackup` 整个文件夹复制到：
   ```
   SillyTavern/public/scripts/extensions/third-party/chat-autobackup/
   ```
2. 重启 SillyTavern
3. 扩展管理 → 找到「聊天记录自动备份 (Chat Auto Backup)」→ 启用
4. 刷新页面，面板标题应显示 `v1.3.2`（没显示说明浏览器缓存了旧代码，Ctrl+F5 强刷）

---

## ⚙️ 首次设置（3 步）

1. 扩展设置面板 → 保存方式选「写入授权目录」→ 点 **选择目录**，挑一个备份根目录（只需授权一次，句柄存在浏览器 IndexedDB 里，之后全自动）
2. 设好 **导出间隔**（默认 50 楼）
3. 开始聊天即可；未授权目录时会自动回退到浏览器下载，不会丢文件

## 🎮 日常使用

在「参数设置 → 备份规则 → 普通备份保留上限」填写每个聊天要留多少份，最少 1 份。比如每 3 楼保存、上限 2 份，聊到第 21 楼时会留下 **10、18、20、21** 楼，其中 10 和 20 楼永久保留。

自动、手动和回溯生成的普通备份一起计数，超出上限时按写入顺序删除最早的一份。高频模式下调低上限会立即清理当前授权目录。旧版文件继续保留，浏览器下载的文件需手动清理。导出间隔设为 10 楼或更大时，各节点均保留。

面板上的按钮：

- **立即备份**：立刻导出当前聊天（整档）
- **回溯备份历史段落（N 段）**：老卡首次启用时用，按间隔把过往楼层补齐
- **忽略历史空档**：不生成文件，只把历史标记为已处理
- **重置本卡计数 / 清理无效计数**：计数错乱时的复位手段

斜杠命令：
```
/cabackup              立即备份
/cabackup interval=30  把导出间隔改成 30 楼
```

```
备份根目录\
└── 星光旅途-歌手版\
    ├── 星光旅途-歌手版.2026.9.1\
    │   ├── 星光旅途-歌手版——林牧和——50.jsonl
    │   ├── 星光旅途-歌手版——林牧和——100.jsonl
    │   └── 星光旅途-歌手版——林牧和——150.jsonl
    └── 星光旅途-歌手版.2026.9.5\        ← 同一张卡的另一个聊天，独立一份
        └── ...
```

聊天文件夹名来自**首楼时间**，格式 `角色卡名.年.月.日`。

## 📐 楼层口径（重要）

> **文件名里的 N = 界面楼层索引 `#N`（0 起）；内容 = `#0` 到 `#N` 的完整快照，共 N+1 条消息。**

```
文件名        内容范围        条数
——50          #0 ~ #50        51 条
——100         #0 ~ #100       101 条
——150         #0 ~ #150       151 条
```

即「每隔 50 层导出」= 在 `#50 / #100 / #150 …` 各出一份**累积快照**（0-50、0-100、0-150），
不是 51-100 这种增量片段。

个别主题的界面楼号口径不同，用设置项 **楼号校准** 微调：界面比面板小 N 就填 `-N`。

## 🆚 和 ST 原生备份的差异

先澄清：**ST 里有两个不同的东西**，别混了。

```
「导出」 聊天列表里的 Export JSONL / Export as TXT 按钮
         → 手动、单文件、整档、落浏览器下载目录

「自动备份」 服务端自动跑的，落 data/default-user/backups/
         → 默认就开着，下面这张表比的是这个
```

原生自动备份的真实机制（我扒了 `src/endpoints/chats.js` 的 `backupChat`，
非猜测）：每次前端保存聊天（`POST /api/chats/save`）都会写一份**整档全量快照**，
用 lodash 节流 10 秒（`throttleInterval`，config.yaml 可调）。

```
维度          ST 原生自动备份                 本扩展
────────────────────────────────────────────────────────────
落盘位置      data/default-user/backups/      你指定的任意目录（授权一次）
触发时机      每次保存聊天，节流 10 秒         每 N 楼一次（默认 50，可配）
文件内容      整档全量快照                     累积切片（0~50、0~100、0~150…）
文件命名      chat_<卡名>_<时间戳>.jsonl      角色卡——USER——楼层数
楼层可读性    ❌ 文件名只有时间戳               ✅ 文件名就是楼层数
中文卡名      ❌ 退化成下划线（见下）           ✅ 完整保留中文
文件组织      ❌ 全部平铺在一个目录            ✅ 角色卡\聊天.日期\ 三层
历史版本      ❌ 每卡滚动留最近 50 份，删最旧   ✅ 高频保存时保留整十楼，普通备份滚动清理
历史回溯      ❌ 只有"现在"这一档              ✅ 一键补齐 50/100/150… 各段
回导入        ✅ 原生格式                      ✅ 带元数据表头，楼号不偏移
多卡隔离      靠文件名前缀，中文卡会串          按 卡ID+聊天ID 计数，物理隔离
```

### 三个真实痛点（都是我实测出来的）

**1. 中文卡名会被吃掉**

源码：`sanitize(name).replace(/[^a-z0-9]/gi, '_').toLowerCase()`
—— 非字母数字**全部替换成下划线**。所以：

```
星光旅途-歌手版  →  chat_____1_20260907-042005.jsonl
                          ↑ 卡名变成一串下划线
```

两张不同的中文卡可能生成**同一个前缀**，然后互相挤占那 50 个名额，
你的旧备份会被另一张卡的备份顶掉。

**2. 高频全量 = 磁盘杀手**

每 10 秒写一份整档。实测你的目录：

```
data/default-user/backups/   932 MB
461 个 jsonl 文件             577 MB
最大的单个文件                16 MB（整档）
05:52:16 / 05:52:41 / 05:57:25 …  同一时段多个 16MB 文件
```

聊天越长越贵：50 份 × 16MB ≈ 785 MB，而内容绝大部分是重复的。

**3. 全是"现在"，没有"过去"**

滚动保留只留最近 50 份，且每份都是当时完整状态——
一旦 50 份滚完，**早期的楼层状态就永久没了**，没法回到"第 100 楼时的样子"。

### 怎么用最合理

**不是替代，是分层**：

- **开着原生自动备份** —— 它是你的"误操作后悔药"，10 秒粒度、自动滚动，什么都不用管
- **装本扩展** —— 按楼层留档，高频保存时仍能回溯到早期的整十楼。

嫌原生太占盘，可以调 `config.yaml`（需重启酒馆）：

```yaml
backups:
  chat:
    enabled: true
    throttleInterval: 10000   # 节流间隔(ms)，调大比如 60000 = 1分钟
  common:
    numberOfBackups: 50       # 每个聊天保留份数，调小比如 20
```

调完原生轻装上阵做"后悔药"，楼层存档交给本扩展。

### 原生备份能关掉吗？

能。改 `SillyTavern\config.yaml`（**改完必须重启酒馆**才生效，
因为 `isBackupEnabled` 是模块加载时读取的常量）：

```yaml
backups:
  chat:
    enabled: false      # ← 关掉聊天自动备份
```

几个要点：

- **只关聊天备份**。世界书、预设、settings 的备份走 `settings.js`，
  用独立逻辑，不受这个开关影响（源码里 `isBackupEnabled` 只在 `chats.js` 内部使用）。
- **关掉不会自动删旧文件**，`backups/` 里已有的 932 MB 还在，要腾空间得手动删。
- **没有前端开关，也没有命令行参数**，唯一入口就是 config.yaml。
- 老版本配置键名是 `disableChatBackup`（反向布尔），新版会自动迁移成
  `backups.chat.enabled`，看到旧写法不用奇怪。

**我的建议是别全关**——聊天文件（`chats/` 目录）是覆盖式保存的，
写完就把上一版顶掉了。原生备份是唯一的"误操作后悔药"，全关了就没有撤销手段了。
更划算的做法是调参瘦身：节流从 10 秒调到 60 秒，每卡保留从 50 份调到 10 份，
体积直接降到约 1/30，但后悔药还在。真要全关，确认你有别的存档手段（比如本扩展）。

## ⚠️ 已知限制

- 目录写入需要浏览器支持 File System Access API（Chrome / Edge 正常）；不支持时自动回退下载
- 回溯依赖当前聊天已加载的完整历史：移动端分页加载的聊天要先滚到底再回溯
- 每次授权目录后若清理浏览器数据，句柄会丢失，需要重新点一次「选择目录」
- 导出内容包含脚本注入的隐藏楼（MVU 变量楼等），所以文件可能比"看得见的对话"大很多——这是刻意为之，回导入才能完整还原

## 🔧 排错速查

- **面板版本号不是 v1.3.2** → Ctrl+F5 强制刷新
- **文件全都是整档、条数一样** → 旧版 bug，升级到 1.1.3+；并把设置项「切片带隐藏楼」保持为 0
- **回导入后楼号少 1** → 旧版缺元数据表头，升级到 1.1.4+ 后重新导出
- **空回或重生成后没更新** → 检查「空回拦截」与「重生成 / Swipe 自动更新」开关是否开启（原地覆写仅在「写入授权目录」模式下生效）
- **面板楼号和界面差固定的 N** → 设置项「楼号校准」填 `-N`
- **没有生成文件** → 检查总开关是否开启、是否已授权目录、导出间隔是否大于当前楼层差
